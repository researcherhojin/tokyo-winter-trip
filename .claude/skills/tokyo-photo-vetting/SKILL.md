# 사진 검수

사진은 「그 장소·상품이 맞는가」만이 아니라 **「카드가 말하는 것을 보여 주는가」**로 고릅니다. 사용자 지적: 「약사진에 건물 사진 이게 맞습니까?」, 「음식 사진으로 해야죠」, 「사진 엄밀하게 검수하고 첨부해야지」.

## 1. 무엇을 찾을지 정하기

카드마다 먼저 한 줄로 정합니다: 「이 카드의 주인공은 ○○」.

| 카드 | 주인공 | 사진 |
| --- | --- | --- |
| 장소(전망·건축·공원) | 장소 | 그 장소의 실제 사진 |
| 식당·카페 | 음식 | 그 가게 음식 → 없으면 같은 종류 음식(「비슷한 참고 사진」) |
| 상품(편의점) | 상품 | 같은 종류 상품·음식(「비슷한 참고 사진」) |
| 의약품 | 상품 종류 | 같은 종류이되 **브랜드가 읽히지 않는** 사진 |
| 매장(굿즈) | 파는 물건·매장 안 | 매장 안·상품 → 없으면 이름 타일 |

**쓰지 않는 사진:** 제조사 본사·공장, 백화점·빌딩 외관, 거리·버스정류장, 다른 가게 간판·광고가 주인공인 사진, 얼굴이 주인공인 사진, 워터마크, AI 이미지, 공식·SNS 사진(약관상 재사용 불가 확인됨).

## 2. 찾기

- Wikimedia Commons(검색·분류·좌표 검색) → Flickr(사진 페이지에 CC BY·BY-SA·CC0·PDM 표시가 있을 때만).
- 라이선스: CC0·Public domain·CC BY·CC BY-SA만. 가로 비율 1.25~1.6 우선. **자르지 않음.**
- 범위가 넓으면 파일을 고치지 않는 조사 에이전트에 맡기고, 결과는 메인이 직접 확인합니다.

## 3. 검수 (반영 전 필수)

```bash
node scripts/contact-sheet.mjs output/photo-review/sheet.html 사진1.jpg:"카드명 → 사진 설명" ...
```

Playwright로 시트를 캡처해 **모든 사진을 직접 봅니다.** 사진마다 확인:

1. 카드의 주인공과 같은 종류인가 (1단계 표)
2. 다른 브랜드·가게가 주인공처럼 보이지 않는가
3. 라이선스·저자·원본 주소·촬영일이 있는가
4. 캡션에 연도, 참고 사진이면 배지(비슷한/판매처/제조사 참고 사진)와 차이 설명이 있는가

통과 못 하면 넣지 않고 이름 타일로 둡니다.

## 4. 사용자 확인

「카드 → 사진(한 줄 설명)」 목록과 접촉 시트를 보여 주고 **승인 후에만** 반영합니다. 대화는 한국어로, 전문 용어는 꼭 필요할 때만 씁니다.

## 5. 반영과 확인

- `src/data/photos.json`에 출처·라이선스·`reference`(배지·차이 설명) 기록, 카드 레코드에 `referencePhotoId` 또는 `photoIds`.
- `npm run photos:archive` → `npm test` → 바뀐 테마 Playwright 캡처 직접 확인 → `npm run qa:browser`.
- 그 다음에만 배포·저장소 업로드. `docs/INTENTS.md`에 결과 기록.
