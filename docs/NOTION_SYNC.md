# Notion 기록과 선택적 일정 연동

## 개발 작업·대화 기록

사용자가 원하는 기본 용도는 개발 작업과 대화의 결정 사항을 여행 페이지에 기록하는 것입니다. 연결된 Codex Notion 도구로 [웹앱 개발 기록](https://app.notion.com/p/3fc6d10af85a813abac6d2062726462e)을 생성하고, 원본 여행 페이지에 바로가기를 추가했습니다. 2026-10-18에 실제 쓰기와 재조회를 확인했습니다. 이 용도에는 아래의 서버 토큰 설정이나 웹앱 배포가 필요하지 않습니다.

기존 일정·예약·첨부는 보존하고, 같은 개발 기록의 현재 상태와 의미 있는 변경 이력을 갱신합니다. 전체 채팅·개인 메시지·실제 키를 복사하지 않습니다. 연결 도구를 통해 작업 중 갱신하는 방식이며 백그라운드에서 모든 대화를 자동 수집하는 기능은 아닙니다.

아래는 별도 기능인 **Notion 시간표 → 웹앱 반영** 안내입니다. 서버 토큰을 사용한 실제 배포 연동은 아직 검증하지 않았습니다.

## 여행 본문에 기록할 내용

2026-10-18 사용자 요청으로 여행에 관한 대화는 원본 본문의 날짜별 추가 메모, 테마별 선택 후보, 준비 체크와 여행 논의·변경 기록에 반영합니다. 개발 이력은 하위 페이지 한 곳으로 연결합니다. 기존 예약·첨부·인라인 데이터베이스와 5일 시간표는 보존하며 새로운 후보를 확정 동선에 모두 넣지 않습니다.

2~5일차 대표 지도는 Google Maps 실제 공유 화면의 ‘지도 퍼가기’에서 얻은 주소를 사용합니다. 대표 위치 지도와 구간별 대중교통 길찾기를 구분합니다. Notion API 저장·재조회, 실제 iframe 표시, 모바일 표시 검증을 각각 구분해 기록합니다. 주소를 직접 새 탭으로 여는 것은 iframe 렌더링 검증을 대신하지 않습니다.

현재 연결된 Codex Notion 도구로 원본 페이지를 읽을 수 있습니다. 2026-10-17에 본문의 상세 일정·숙소 주소를 확인했습니다. 이 도구의 로그인 권한이 배포한 웹앱으로 전달되지는 않습니다.

## 구현 범위

`server/notion.ts`는 원본 페이지의 첫 번째 1~5일차 토글 안에서 **`시간 / 일정 / 이동·실행 방법`의 3열 표**를 읽습니다. 시간·제목·메모가 웹앱 일정에 반영됩니다. 날짜별 사진과 중복 상세 시간표를 제거한 현재 구성은 기존 3열 표 읽기와 호환됩니다. 이전의 ‘시간표·교통 상세’ 토글 및 직접 노출된 세로 일정도 계속 지원합니다. 세로 형식은 첫 줄의 `10:00–14:30 · 해리포터 스튜디오`와 줄바꿈 뒤 이동·확인 메모를 읽습니다. 지도·증빙·후보 토글 안으로는 들어가지 않습니다. 이미 검증된 장소명은 기존 좌표와 연결합니다. 새로운 장소의 좌표·영업시간·사진은 자동 생성하거나 확정하지 않습니다. 방문 가이드, 장소 상세, 숙소 주소, 체크리스트는 검증된 로컬 데이터로 유지하며 변경 시 별도 검토가 필요합니다.

항공권·입장권 PDF, QR, 결제 내역, 예약 번호와 숙소 호실은 읽거나 응답에 포함하지 않습니다. 원본의 여행자 이름은 표시 전에 제거합니다. API 응답은 배포 주소를 아는 사람이 읽을 수 있는 여행 시간표이므로 원본 표에는 공개하면 안 되는 정보를 넣지 마세요. 일반 메모의 모든 개인정보를 자동 판별하는 기능은 아닙니다.

## 서버 키 설정

1. Notion에서 읽기 권한만 가진 integration을 생성합니다.
2. 해당 integration에 여행 원본 페이지를 연결합니다. 페이지 ID는 코드에 고정되어 있습니다.
3. Vercel 프로젝트 환경변수에 **`NOTION_API_TOKEN`**을 등록합니다. 브라우저에 노출되는 `VITE_` 접두사를 붙이지 않습니다. `.env.example`은 요청대로 지도 변수 하나만 유지합니다.
4. 환경변수 설정 후 승인된 배포를 수행합니다. 토큰을 채팅·소스·스크린샷에 붙이지 않습니다.
5. `/api/trip`이 `enabled:true`와 5일치 표를 반환하고 화면에 `Notion 자동 반영`이 표시되는지 확인합니다.

Vercel 진입점은 `api/trip.ts`, Cloudflare 대안은 `functions/api/trip.ts`입니다. 둘 다 같은 서버 로직을 호출하고 GET만 허용합니다. 로컬 Vite는 공통 middleware를 사용합니다. 서버 토큰이 없으면 `{enabled:false}`로 정적 일정을 유지합니다. 서버 로직은 모의 Notion 응답을 사용하는 자동 테스트로 검증했습니다. 실제 integration 토큰을 사용한 배포 통합 검증은 아직 하지 않았습니다.

## 갱신과 실패 처리

화면이 보이는 동안 60초마다 확인하며 다시 탭으로 돌아올 때도 갱신합니다. 서버 인스턴스의 정상 응답은 60초 동안 재사용하고 동시 요청을 합칩니다. 전역·영구 캐시가 아니므로 다른 인스턴스는 별도 조회할 수 있습니다. 현재 3열 표는 원본 페이지1회·최상위 블록1회·일차 토글5회·표 행5회로 **한 번 갱신에 약12회** Notion 요청입니다. 이전의 바로 노출된 세로 일정은 약7회, 이름으로 지정한 상세 토글 방식은 약12회입니다. 추가 페이지네이션이 있으면 증가하며 총30회로 제한합니다. 요청 시작 간격과 전체12초 제한을 적용했습니다.

표 누락·형식 변경·인증 오류·속도 제한·네트워크 오류는 불완전한 일정을 적용하지 않습니다. 열린 탭의 마지막 정상 일정을 유지하고 `갱신 지연`을 표시합니다. 새로 접속하면 기본 정적 일정에서 시작합니다. 브라우저 체크리스트는 원본 예약 상태와 별개이며 동기화하지 않습니다.

현재 표는 `시간 / 일정 / 이동·실행 방법` 순서와 3열을 유지합니다. 이전 세로 형식은 `시간 · 일정 제목`과 줄바꿈 뒤 메모를 같은 글머리 항목 안에 둡니다. 잘못된 시각·메모 누락·일차 누락은 업데이트를 거부합니다. 바뀐 메모는 예약 확정 여부로 자동 해석하지 않고 원문을 표시합니다. 인라인 데이터베이스·첨부 티켓 원문 검증은 별도 범위입니다.
