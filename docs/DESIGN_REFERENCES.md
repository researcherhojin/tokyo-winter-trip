Notion 마켓플레이스의 설명뿐 아니라 실제 미리보기 화면을 Chrome에서 열어 비교했습니다. 템플릿을 설치하거나 제작자의 이미지·일러스트·내용을 복제하지 않았습니다.

페이지 분리 후 사용자가 지정한 디테일을 반영했습니다. 항공·숙소는 역할이 분명한 두 콜아웃으로 구성하고, 숙소에 실제 공유한 Airbnb 주소를 연결합니다. 제목 바로 아래에 구분선을 두고, 토글을 연 뒤 첫 문장 앞과 본문 끝에 여백을 둡니다. 사용자가 직접 수정한 일차별 여백·제목은 보존하고 같은 규칙을 하위 페이지에 적용합니다. 배경색을 남발하지 않도록 기본 강조는 페이지별 핵심 섹션 한 곳에만 두며, 사용자의 직접 편집은 덮어쓰지 않습니다.

- 여행 홈: 항공·숙소 기본 정보, 날짜별 일정 5개, 여행 도구 4개.
- 테마 탐색: 야경·사진·먹거리·카페·근교 후보. 확정 일정과 구분.
- 준비 체크: 세 그룹의 실제 체크박스를 바로 표시. 긴 Suica·환율 안내만 펼침.
- 예약·항공권: 항공권·티켓·결제·숙소 원본 보관.
- 교통·공식 자료: 노선·영상·사진 출처·디자인 참고·변경 기록. 원본 데이터베이스와 기존 개발 기록도 삭제하지 않고 이 페이지 아래로 이동.

시각 규칙은 Notion 기본 산세리프, 검정 본문·회색 보조문, 흰 배경, 기본 파란 링크입니다. 지원하지 않는 임의 CSS·서체·카드 모양을 흉내 내지 않습니다. 날짜별 사진은 사용자 요청으로 제거하고, 상세 43개를 `시간 / 일정 / 이동·실행 방법`의 3열 표로 표시합니다. 노선·환승·도보·현장 행동과 미확정 상태를 같은 행에서 읽습니다. 중복되던 상세 시간표 토글은 제거하고 기존 일정 메모는 공식 자료 토글에 보존했습니다. 표 아래에는 날짜별 확인·할 일과 지도·공식 자료를 둡니다. 좁은 화면에서는 Notion 표 영역 안에서 좌우로 스크롤하며 문서 전체 폭을 늘리지 않습니다.

테마 탐색 사진과 표지는 유지하고 날짜별 장식 사진 5개는 제거했습니다. 표지는 사용자의 요청에 따른 도쿄타워 야경입니다. 가로 구도의 [Minato City, Tokyo, Japan (Night)](https://commons.wikimedia.org/wiki/File:Minato_City,_Tokyo,_Japan_(Night).jpg), David Kernan, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0)이며 실제 원본을 보고 선정했습니다. 원본·저작자·라이선스는 Notion의 교통·공식 자료와 표지 하단에 표시합니다. 본문 자료 사진 출처는 public/photos/LICENSE.md에 있습니다. 날짜별 장식 사진 제거와 원래 예약 증빙 이미지 8개 보존을 구분합니다.

## 개편 전 화면의 문제

1. 사진·설명·주의 문구가 먼저 이어져 모바일에서 실제 시간표가 늦게 보입니다.
2. 화면 상단의 전역 날짜 바와 일정 탭이 차지하는 높이가 큽니다.
3. 방문 장소 사진이 장소 목록과 떨어져 있어 사진과 일정이 하나의 사용 흐름으로 읽히지 않습니다.
4. 지도는 PC에서 크게 보이지만 모바일에서는 목록과 완전히 분리됩니다.
5. 색상·모서리·브랜드 변경을 반복했지만 정보 구조와 조작 방식의 변화가 부족했습니다.

## 제안하는 방향

**Tripsy의 간결한 여행 도구 구조를 주축으로 삼고, 장소 식별을 돕는 사진을 결합합니다.** PC는 지도와 간결한 일정 패널, 모바일은 지도와 확장 가능한 일정 시트 구조를 우선 검토합니다. 일정 행은 시간·장소·작은 사진·이동 요약을 중심으로 하고, 긴 설명과 출처는 명확한 상세 동작으로 연결합니다. 예약 미확정 정보는 숨기지 않고 해당 일정 가까이에 둡니다.

지도·날짜·일정·길찾기의 정보 구조를 먼저 결정한 뒤 타이포그래피·간격·색상·사진 비율을 하나의 시스템으로 정합니다. 기존 blue 버튼을 다른 색으로 교체하는 것만으로 완료하지 않습니다. 상세 기능을 줄이거나 계획을 확정 정보로 바꾸지 않습니다.

## 다음 구현의 성공 조건

- 모바일 첫 화면에서 선택 날짜, 지도와 일정의 관계, 첫 방문 시간·장소를 확인할 수 있음.
- 장소를 선택하면 대응하는 지도 핀과 상세 정보가 일관되게 연결됨.
- 장소 사진이 해당 일정 행 또는 상세에 연결되고 출처를 확인할 수 있음.
- 320px~1440px에서 주요 조작 44px, 본문 16px, 대비 4.5:1을 유지함.
- 다섯 날짜·전체 일정·예약 불확실성·체크리스트·키 없는 대체 화면의 기존 동작 보존.

위 검토를 바탕으로 PC 전체 지도 위의 날짜·일정 패널, 모바일의 확장 가능한 일정 시트, 장소 행의 작은 사진, 펼쳐 보는 이동·메모를 구현했습니다. 검증 결과는 DESIGN_REVIEW.md와 VERIFICATION.md에 기록합니다. 자동 검사 통과가 사용자의 시각적 선호 승인을 뜻하지 않습니다.

## 테마 카드 사진 · Airbnb 검색 결과 카드 · 2026-10-18

사용자 요청으로 Airbnb 도쿄 숙소 검색 결과 화면을 실제 Chrome에서 열어 카드 사진 구조를 측정했습니다. 사진·브랜드는 복사하지 않았습니다.

| 관찰 | 측정값 | 이 앱에 적용한 판단 |
| --- | --- | --- |
| 카드 상단 사진 프레임 | 328×246px, `aspect-ratio: 4/3`, 테두리 없는 둥근 모서리 | 4:3 프레임과 12px 모서리를 사용합니다. 카드 테두리는 정보량이 많아 유지합니다 |
| 사진 맞춤 | `object-fit: cover`(세로 사진도 잘림) | **사용자 요청으로 자르지 않습니다.** 원본 전체를 같은 사진의 흐린 배경 위에 둡니다 |
| 사진 위 요소 | 왼쪽 위 「게스트 선호」 배지, 오른쪽 위 위시리스트 하트 | 왼쪽 위 상태 배지, 오른쪽 위 저장 버튼(44px 이상)을 사진 위에 둡니다 |
| 여러 장 | 아래 가운데 점, 마우스를 올리면 이전/다음 버튼 | 스크롤 스냅 캐러셀·점·이전/다음 버튼. 터치 기기는 버튼 대신 밀기 |
| 사진 아래 | 제목·평점·짧은 정보 | 이름·한 줄 설명·운영시간·휴무 |

참고 사진(비슷한 사진)은 Airbnb에 없는 요소입니다. 실제 장소가 아니라는 사실을 숨기지 않도록 사진 위 배지와 사진 바로 아래 차이 문구를 함께 둡니다.
