# 개발 흐름과 사용한 프롬프트

이 앱을 Claude Code로 개발한 방식입니다. 요청별 진행 상태는 [INTENTS.md](INTENTS.md)에 있습니다.

## 한 요청이 처리되는 순서

1. **접수:** 요청을 [INTENTS.md](INTENTS.md)에 번호로 적고 완료 기준을 정합니다.
2. **재현:** Playwright로 해당 화면을 열어 캡처하거나 측정합니다(1440·1024·390·320px).
3. **조사:** 여행 정보는 공식 페이지만 근거로 씁니다. 범위가 넓으면 조사 에이전트에 나눠 맡기고, 에이전트는 파일을 고치지 않고 결과만 돌려줍니다.
4. **적용:** 메인 세션이 데이터·컴포넌트를 고칩니다. 같은 파일을 여러 에이전트가 동시에 고치지 않습니다.
5. **검증:** `npm run check` → Playwright 캡처 확인 → `npm run qa:browser` → 키 없는 `dist` 빌드.
6. **기록:** INTENTS 상태, `docs/VERIFICATION.md`, `docs/PROJECT_STATUS.md`를 갱신합니다.

## 조사 에이전트에 준 프롬프트 형식

모든 조사 에이전트에 아래 규칙을 넣었습니다.

```text
DO NOT EDIT ANY FILE. Return findings only.
Official = 운영사·구청·정부·JNTO/GO TOKYO·운영사가 직접 낸 보도자료.
Listing sites, news, blogs, search snippets do NOT count.
막히는 공식 페이지(403/404)는 실제 브라우저(Playwright 별도 세션)로 다시 엽니다.
Only report what you actually opened.
각 결과: {파일, 위치, 현재 문구, 상태(official-ok|update|unverifiable-remove|add), 제안 문구, 공식 URL, 짧은 원문 인용}
```

사진 조사 에이전트에는 다음을 추가했습니다.

```text
허용 라이선스: CC0, Public Domain, CC BY, CC BY-SA. NC/ND·공식 사이트·SNS·AI 이미지 금지.
간판·주소·좌표로 그 가게·장소임을 확인한 사진만. 내려받은 사진은 직접 열어 확인.
```

## 작업이 밀릴 때 확인하는 법

[Claude Code 대화형 모드 문서](https://code.claude.com/docs/en/interactive-mode) 기준입니다.

- 보낸 메시지가 회색이면 아직 읽지 않은 것입니다. 실행 중인 도구 호출이 끝나면 전달됩니다.
- 급한 요청은 `Ctrl+Enter`로 바로 보냅니다. 끊지 않고 진행 상황만 물을 때는 `/btw`를 씁니다.
- `/tasks`는 백그라운드 셸·에이전트 목록을 보여줍니다.
- 오래 걸리는 명령(예: 영상 프레임 추출)은 메시지 전달을 막으므로 짧게 나누거나 쓰지 않습니다.
