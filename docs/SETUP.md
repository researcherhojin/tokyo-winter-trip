# 설치·실행·기능 상세

> 프로젝트 소개는 [README](../README.md), 현재 수치는 [PROJECT_STATUS](PROJECT_STATUS.md)를 기준으로 합니다. 아래는 설치·지도 키·기능 설명의 상세본입니다.

2026년 12월 11~15일, 3인의 도쿄 여행을 위한 React + TypeScript + Vite 웹앱입니다. Notion 원본 일정을 2026-10-17에 읽어 반영했습니다. 2026-10-18 사용자 요청으로 원본 아래에 개발 기록과 바로가기를 추가했으며, 기존 여행 일정·예약·첨부는 보존했습니다.

## 로컬 실행

Node.js 22.12 이상과 npm이 필요합니다.

```bash
npm ci
npm run dev
```

브라우저에서 `http://127.0.0.1:5173`을 엽니다. `npm start`도 같은 주소로 실행합니다. 키가 없어도 날짜별 일정, 방문 순서 개략도, 장소 상세, 공식 안내, Google Maps 길찾기와 체크리스트를 이용할 수 있습니다.

```bash
npm run check            # 빌드·동작·철자·키 패턴 통합 검사
npm run qa:browser       # 실행 중인 로컬 앱을 실제 Chrome으로 검사
npm test                 # TypeScript·배포 빌드 후 DOM 통합 테스트
npm run security:scan    # 소스·dist의 키/토큰 패턴 검사
npm run spellcheck       # 소스·문서·빈 환경변수 템플릿 철자 검사
npm run build
npm run preview          # 배포 결과 미리보기: 기본 4173 포트
```

의존성 설치·빌드·자동 테스트를 완료했습니다. 초기 샌드박스 제한은 권한 변경 후 해결되어 Playwright로 실제 Chrome·Google 지도 연결, 날짜별 마커, 상세 모달, 체크리스트 저장, 요청 차단·복구를 확인했습니다. PC 1440×900과 모바일 폭 390px·320px도 검증했습니다. 실제 휴대폰과 배포 후 Notion 임베드는 남은 확인 항목입니다. 자세한 결과는 `docs/VERIFICATION.md`와 `output/playwright/` 화면 캡처에 있습니다.

## Google 지도 연결

정확한 변수명은 **`VITE_GOOGLE_MAPS_API_KEY`**입니다. `GOOGLE_MAPS_API_KEY`, `VITE_MAPS_API_KEY` 등 다른 이름은 읽지 않습니다. 루트의 `.env` 또는 `.env.local`에 `VITE_GOOGLE_MAPS_API_KEY=발급받은_키` 형태로 설정하세요. 둘 다 있으면 Vite는 `.env.local`을 우선합니다. 환경파일 변경 후 실행 중인 서버를 Ctrl+C로 종료하고 `npm run dev`로 재시작하세요. 키 값은 출력하거나 공유하지 않습니다.

`Download the React DevTools…`는 개발 편의 안내입니다. `ERR_BLOCKED_BY_CLIENT`는 브라우저나 확장 프로그램의 요청 차단입니다. `gen_204?csp_test=true` 한 요청의 차단만으로 키 오류를 단정하지 않습니다. 실제 지도 스크립트·라이브러리 요청의 차단 여부와 Console의 Google Maps API 오류를 함께 확인하세요. 앱의 지도 연결 도움말에도 같은 안내가 있습니다.

`.env.example`을 `.env.local`로 복사하고 본인의 브라우저용 키를 로컬에서 입력합니다. 키를 채팅·커밋·스크린샷에 붙이지 마세요.

```bash
cp .env.example .env.local
```

`VITE_GOOGLE_MAPS_API_KEY`를 입력한 뒤 개발 서버를 재시작합니다. Vite 환경변수는 빌드 시 치환되므로 배포 키 변경 시 재빌드해야 합니다.

- Google 프로젝트: **Travel Map / travel-map-511913**.
- 사용하는 API: **Maps JavaScript API만**. Google의 공식 직접 스크립트 로딩 방식과 `importLibrary('maps')`, `importLibrary('core')`, `importLibrary('marker')`, `AdvancedMarkerElement`를 사용합니다.
- 별도의 React 지도 래퍼·Places·Geocoding·Routes API는 사용하지 않습니다. 이동은 API 키 없이 작동하는 Google Maps URLs입니다. 시간표·운임·실시간 운행을 앱 안에서 조회하지 않습니다.
- 지도 로딩 시만 Google 요청이 발생합니다. 키 미설정이면 Google 지도 스크립트를 요청하지 않습니다. 오류 시 일정·개략도·외부 길찾기를 유지합니다.
- Advanced Markers에는 Map ID가 필요해 현재 공식 예제용 `DEMO_MAP_ID`를 사용합니다. 실제 배포 전 Google Cloud의 JavaScript Map ID를 준비해 `src/components/TravelMap.tsx`의 `mapId`를 교체하세요. Map ID는 비밀키가 아닙니다.
- 브라우저용 키는 지도 실행 시 브라우저에 전달됩니다. `.env.local`은 저장소 유출 방지 수단이며 브라우저에서 키를 숨기는 방법은 아닙니다. 실제 HTTPS 배포 주소 확정 후 **HTTP 리퍼러 제한**과 기존 **Maps JavaScript API 제한**을 적용해야 합니다. 세부 절차는 배포 가이드에 있습니다.
- 로컬 키 패턴 검사 통과는 GitHub 전체 이력의 유출 부재를 증명하지 않습니다. 현재 이 폴더에는 `.git`과 GitHub 원격 저장소가 없습니다.

## 구현된 기능

- 5개 날짜 및 전체 일정 선택, `?day=1`~`5`, `?day=all` 직접 링크·뒤로 가기.
- 날짜별 장소 필터, 번호 마커, 지도 범위 자동 조절, 마커와 상세 정보 연결. 같은 장소 재방문은 같은 번호를 쓰고 상세 일정에서 순서를 설명합니다.
- PC 지도·일정 분할, 760px 이하 지도·일정 전환, Notion 임베드에 적합한 높이·스크롤.
- Notion 상세 시간표, 필수·선택 구분, 체류 계획, 환승 안내와 출발·도착지가 지정된 대중교통·도보 링크.
- 공식 주소·층수, 운영시간 확인 기준, 입장·예약 안내, 체험 요약, 공식 출처·좌표 출처 링크.
- 날짜별 방문 가이드와 공식 자료·영상 링크. Notion에 있던 영상 중 재검증하지 않은 것은 확인 필요로 표시합니다.
- localStorage 체크리스트, 손상·저장 제한 대응, JSON 백업·복원. 기기·일행 간 자동 동기화는 없습니다. 체크는 예약 상태를 변경하지 않습니다.
- 키 미설정·연결 실패 대체 화면, 키보드 포커스·모달, 인쇄용 일정 스타일.

테스트는 실제 로컬 키를 비우고 `output/test-build`에 별도로 빌드합니다. 기존 `dist`는 덮어쓰지 않습니다. `npm run build`로 배포 빌드를 다시 생성할 수 있습니다.

## 정보의 확실성

시간과 체류·이동 소요는 **Notion의 계획값**입니다. 항공편은 공유된 시각 기준이며 일행 전체 항공권은 별도 확인합니다. 해리포터 10:00은 일행 합의로 결제 미확인입니다. 포케파크는 티켓 3장의12/12 Trainer’s Pass·포레스트11:00–12:00 입장을 확인했습니다. 숙소는 결제 기록과 별도로 예약 확정·짐 보관 조건을 확인해야 합니다. 첨부 QR/PDF·예약 번호·결제 금액·숙소 호실은 앱에 복사하지 않았습니다.

숙소는 Notion 원본의 **東京都港区新橋5丁目29**를 별도로 표시합니다. 국토지리원 주소 검색으로 확인한 주소 구역 대표점이며 정확한 건물 입구는 예약 안내로 확인해야 합니다. 신바시역 핀과 구분했습니다. 공원·단지·역·쇼핑 지역 핀은 대표 위치이며, 특히 요미우리랜드 핀은 포케파크 전용 출입구가 아닙니다. 입구와 매장 층수는 공식 안내를 확인하세요. 원본 Notion의 인라인 데이터베이스·첨부 티켓 원문까지 검증한 것은 아닙니다.

공식 주소와 좌표 출처, 수집 범위·불확실성은 [자료 검증 기록](DATA_SOURCES.md)에 있습니다. 12월 운영·요금·일몰·열차는 방문 전에 다시 확인해야 합니다.

[AGENTS.md](../AGENTS.md)에 반복되는 경계·검증 지침을, [개발 절차](WORKFLOW.md)에 공식 Codex 문서를 참고한 진행 방식을 추가했습니다. 모델을 여러 개 거치는 체인을 필수로 두지 않습니다. [공식 제품 레퍼런스](DESIGN_REFERENCES.md)를 검토한 뒤 PC 전체 지도·일정 패널과 모바일 일정 시트로 개편했습니다. 시간·장소·작은 사진·길찾기를 우선 표시하고 메모·환승 설명은 펼쳐 봅니다.

**준비 체크**에서는 체크리스트를 먼저 보여주고 보조 영역에 Frankfurter 일별 JPY/KRW 참고 환율과 경비 환산을 제공합니다. 은행 환전 시세와 다르며 응답 기준일을 표시합니다. Suica 준비 가이드·스타워즈 입장 안내도 추가했습니다. [여행 정보 출처·불확실성](TRAVEL_TIPS.md)을 참고하세요. 실시간 식당 평점·리뷰를 앱 안에서 가져오는 Places API는 활성화하지 않았습니다.

## 화면별 API와 상세 안내

화면 주소도 공유할 수 있습니다: 여행 지도 `/?day=3`, 전체 일정 `/?day=all`, 테마 `/?day=3&view=themes`, 준비 체크 `/?day=3&view=checklist`. 새로고침과 브라우저 뒤로/앞으로 가기에서 화면과 선택 날짜를 유지합니다.

여행 지도·테마 탐색·준비 체크는 각각 `/api/catalog/trip`, `/api/catalog/themes`, `/api/catalog/preparation`을 소비합니다. 로컬 Vite에서도 JSON을 반환하며, 서버 기능이 없는 정적 배포나 잘못된 응답에서는 번들 자료로 계속 사용할 수 있습니다. API는 배포한 여행 안내를 조회하는 용도이며 개인 체크는 로컬에 저장합니다. 계약은 [API 문서](API.md)에 있습니다.

세 화면에 공통 디자인 토큰을 적용하고 장소 15곳에 소개·추천 방문 순서·접근·예산·현장 주의·공식 출처를 보강했습니다. Codex 공식 문서를 참고한 담당 분리와 완료 기준은 [개발 절차](WORKFLOW.md)에 기록했습니다. 개발 기록은 [Notion 개발 페이지](https://app.notion.com/p/3fc6d10af85a813abac6d2062726462e)에 갱신합니다.


## 여행 중 빠른 확인
