# 만든 과정: 프롬프트와 작업 흐름

이 앱은 Claude Code(Claude Opus)와 한국어 대화로 만들었습니다. 사용자가 화면을 보고 요청하면, Claude Code가 요청을 장부에 적고 → 구현하고 → 테스트와 실제 브라우저(Playwright)로 확인한 뒤 → 문서를 갱신하는 흐름을 반복했습니다. 요청별 완료 기준과 근거는 [INTENTS.md](INTENTS.md)(#1~#59)에 있습니다.

## 작업 흐름

```
사용자 요청(대개 스크린샷 + 한 줄)
  → docs/INTENTS.md에 번호·완료 기준 추가
  → 재현: Playwright로 해당 화면 측정·캡처 (1440·1024·390·320px)
  → 조사가 필요하면 조사 에이전트에 위임 (파일 수정 금지, 결과만 반환)
  → 메인 세션이 구현
  → npm test → Playwright 측정·캡처 직접 확인 → npm run qa:browser
  → 같은 유형을 전체 화면에서 찾기 (scripts/full-sweep.js: 26개 상태 × 4개 폭)
  → INTENTS · VERIFICATION · PROJECT_STATUS 갱신
```

이 흐름은 프로젝트 스킬 [`.claude/skills/tokyo-detail-audit`](../.claude/skills/tokyo-detail-audit/SKILL.md)로 저장해 매번 같은 순서로 돌게 했고, 고친 요청이 다시 깨지지 않도록 [`scripts/intent-scenarios.mjs`](../scripts/intent-scenarios.mjs)가 요청 번호별로 검사합니다.

## 단계별 대표 프롬프트

사용자가 실제로 보낸 요청입니다(원문, 일부 축약).

### 1. 정보의 정확성

- 「공식적으로 발표된 거 기반으로만 해주시고, 각 테마 별 장소에 대한 설명이나 여행 지도에서 일자별 장소 설명에서도 업데이트가 필요한 영역에 대해서 업데이트 해주시겠어요?」
- 「이것도 만약에 실제로 사진이 없다라거나 그렇다면 차라리 빼주세요.」

→ 공식 출처 대조 조사 에이전트 4개, 보도·지난해 값 제거, 근거 없는 후보 삭제. 규칙은 [CLAUDE.md](../CLAUDE.md) 「리뷰 기준」에 고정.

### 2. 사진

- 「먹는 곳에서 가게에 대한 실제 사진이 있어야 하는데 그렇지 못한 곳이 있다면 사진을 엄밀하게 찾아서 첨부해주세요.」
- 「각 장소 별로 사진이 3장 이상은 있어야 될 거 같다는 느낌이 있어서요.」
- 「공식 사이트로 연결하기 보다는 그 이미지 가져오고 저작권 표시 하면 되지 않나요?」

→ Commons·Flickr 자유 라이선스만, 좌표·간판으로 장소 확인 후 직접 열어 확인, 자르지 않음. 공식·보도자료 이미지는 22개 브랜드 약관을 확인해 재사용 불가로 판단. 대신 배지를 붙인 참고 사진(제조사 건물·판매처 거리)을 사용.

### 3. 화면 디테일

- 「카드 길이가 일치하지 않는데, 이런 거 통일감 있게 하기 위한 작업도 해주세요.」
- 「모든 테마 별로 프레임이 같아야 가독성이 좋을 거 같은데… 엄밀하게 작업을 해주세요.」
- 「이렇게 깨지는 거나 텍스트 잘리지 않게 해주세요. 혹은 상세한 정보는 모달 안에 담아서 깔끔하게 보이게 해주시던가요」
- 「준비 체크도 탭 별로 봐서 한 페이지에 보이도록 조치해주시구요」

→ subgrid로 카드 행 정렬, 테마 머리 높이를 13개 테마 한 값으로 측정·고정, 상세는 정보 창으로, 준비 체크 단계 탭.

### 4. 레퍼런스 기반 설계

- 「그냥 개발하지 말고, 레퍼런스를 찾고 레퍼런스가 어떻게 개발했는지 확인한 다음에 우리의 시스템에 적용해주세요.」

→ Google Maps·Airbnb 화면을 Playwright로 측정(패널 폭, 지도 시작 위치, 컨트롤 위치)한 뒤 여행 지도 프레임에 적용. 측정값은 [DESIGN_REFERENCES.md](DESIGN_REFERENCES.md).

### 5. 스스로 찾기·누락 방지

- 「제가 이렇게 하나씩 찾아서 진행하기 보다는 당신도 충분히 찾거나 디테일적으로 손 볼 부분을 알 수 있을 겁니다.」
- 「기능은 구현하면 테스트 및 playwright로 확인 후 다음 단계로 진행해주세요. 지금 보면 누락되는 부분들이 꽤 보입니다.」

→ 요청 장부(INTENTS), 요청 회귀 검사, 전체 화면 자동 점검, 프로젝트 스킬 추가.

### 6. 구조·배포

- 「모듈 레이어 서버 인프라 작업이 엄밀하게 되고 있는 건가요?」
- 「cloudflare에 배포해도 될까요?」 「배포할 때 이름도 추천 받습니다.」

→ 테마 데이터를 후보 1곳 = 1레코드로 재구성, CSS를 화면별로 분리(계산 스타일 비교 차이 0), 화면별 코드 분할. Cloudflare Pages `tokyo-winter-trip`에 배포하고 지도 키는 웹사이트 제한·일일 상한·예산 알림을 건 뒤 포함.

### 7. 사진 검수 강화

- 「그런데.. 약사진에 건물 사진 이게 맞습니까?」 「도 음식 사진으로 해야죠..」
- 「당신 사진 엄밀하게 검수하고 첨부해야지」 「이러면 배포 못 하죠..」
- 「claude나 codex 스킬로 처리 할 수 있지 않을까요?」

→ 제조사 건물·매장 외관·거리 사진 13장을 모두 빼고, 카드와 같은 종류(음식·상품)만 쓰는 규칙을 [사진 검수 스킬](../.claude/skills/tokyo-photo-vetting/SKILL.md)로 만듦. 접촉 시트(`scripts/contact-sheet.mjs`)로 한 장씩 확인하고, 사용자 승인 후에만 반영·배포.

### 8. 전달 방식

- 「한국말로, 제가 진행해야하는 것을 단계 별로 알려주세요. 페이지도 열어주시구요」 「전문 용어 제외하고는 한국어로 하라고 했을텐데요」

→ Google Cloud 키 제한·하루 상한·예산 알림을 화면 캡처를 받아 가며 한 단계씩 안내. 이후 모든 보고를 쉬운 한국어로.

### 9. 공개

- 「지금 작업한 거 github에 올리면서 해당 작업을 하면서 사용한 prompt와 작업 flow도 문서화 작업 가능할까요?」 「github repo도 당신이 만들어주시고, 리드미도 깔끔하게 작업해주세요.」 「.gitignore 처리 엄밀하게 해주세요.」

→ 이 문서, README 다이어그램, 비밀 값·빌드 결과·도구 상태를 제외한 .gitignore.

### 10. 공개 이후 다듬기

- 「가독성 좋게 해주시고, readme.md도 오피셜하게 간단 명료하게 작업해주세요.」 「…누가 이렇게 리드미에 남겨요..」 「진짜 엄밀하게 해주세요.」
- 「페이지 상단에 Github도 보이게 가능할까요? 노션으로 가는 버튼 옆이요? 혹은 더 나은 방안이 있으면 그걸로 제안해주세요.」
- 「노션 페이지 편집 권한 claude도 있나요?」 「.md들과 개발 flow, 프롬프트, 문서도 업데이트 되어 있나요?」

→ README를 화면 캡처·짧은 표·그림 2개로 다시 쓰고, 문장 하나하나를 데이터와 대조해 틀린 2곳을 고침. 코드 MIT 라이선스(사용자 선택). 상단 Notion 옆에 GitHub 아이콘, 휴대폰은 테마 탐색 하단 안내에 링크. Notion은 연결에 공유되지 않아 404 → 사용자 공유 필요. 매 단계 뒤 문서 갱신 여부를 다시 확인.

## 조사 에이전트에 준 프롬프트 형식

넓은 조사는 파일을 고치지 않는 에이전트에 나눠 맡기고, 메인 세션이 결과를 직접 확인해 반영했습니다.

```text
DO NOT EDIT ANY PROJECT FILE. Return findings only.
Official = 운영사·구청·정부·관광청이 직접 낸 자료. 보도·리스팅·검색 요약은 제외.
Only report what you actually opened.
각 결과: 현재 문구 / 상태 / 제안 문구 / 공식 URL / 짧은 원문 인용
```

사진 조사에는 다음을 더했습니다.

```text
Licences: CC0, PD, CC BY, CC BY-SA only. No NC/ND, official sites, SNS, AI images.
Confirm identity by description, geotag or visible signage. VIEW every image yourself.
Landscape (w/h 1.25–1.6) preferred; photos are never cropped.
Return: file page, download URL, W×H, author, licence + URL, date, Korean caption with year, identity evidence.
```

전체 형식과 조사 목록은 [DEV_FLOW.md](DEV_FLOW.md).

## 배운 점

- **스크린샷 한 장 = 같은 유형 전체.** 한 화면의 지적을 고치면 같은 유형을 13개 테마·5일·4개 폭에서 측정해 확인했습니다.
- **측정으로 말하기.** 「간격 통일」은 「카드 시작 위치가 13개 테마에서 한 값」처럼 숫자로 확인했습니다.
- **반복되는 지적은 규칙으로.** 같은 지적이 두 번 나오면 CLAUDE.md 리뷰 기준에 한 줄로 추가했습니다.
- **외부 작업은 확인 후.** 배포·저장소 공개·결제 설정은 사용자 승인 후에만 진행했고, 비밀 키는 출력·커밋하지 않았습니다.
